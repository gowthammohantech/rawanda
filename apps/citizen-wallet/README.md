# Citizen Health Wallet (`@laif/citizen-wallet`)

> **DEMONSTRATION — SYNTHETIC PATIENT DATA — NOT FOR CLINICAL USE.** Every person, record,
> facility and phone number in this app is made up. The wallet never gives a diagnosis or
> treatment advice, never shows a health score, and is never used for insurance or credit
> decisions.

Expo (React Native) + Expo Router app for citizens: released results in plain language, the
next steps their care team approved, reminders, a progress timeline, privacy (access history,
corrections) and support — in English and Ikinyarwanda. Isolated dataset (D3): the app runs
entirely on the device (`expo-sqlite` on phones, IndexedDB on the Expo web target) and makes no
network calls.

## Run

| What                                                       | Command                                                           |
| ---------------------------------------------------------- | ----------------------------------------------------------------- |
| Dev server (Expo Go / dev build, port 8082)                | `pnpm dev:citizen` (= `pnpm --filter @laif/citizen-wallet start`) |
| Web target                                                 | `pnpm --filter @laif/citizen-wallet web`                          |
| Typecheck / lint / unit + screen tests                     | `pnpm --filter @laif/citizen-wallet typecheck` · `lint` · `test`  |
| Web build (static export to `dist/`)                       | `pnpm --filter @laif/citizen-wallet build`                        |
| Web E2E (journeys on the web export, port 8092)            | `pnpm --filter @laif/citizen-wallet test:e2e`                     |
| Device E2E (Maestro, emulator / simulator running the app) | `pnpm --filter @laif/citizen-wallet test:maestro`                 |
| Translation check + review list                            | `pnpm i18n:check --ns citizen --report`                           |

`EXPO_PUBLIC_LAIF_E2E=1` builds skip the simulated network latency (used by the web E2E).

## Reset and demo tools

**More → Demo tools** (also on the welcome screen footer before a persona is chosen). Everything
here is labelled DEMO ONLY.

- **Reset demo** — reseeds the citizen dataset to the baseline (same dataset hash), clears faults,
  and restores language English, standard text size, high contrast off.
- **Demo clock** — the clock is pinned to 14 Oct 2026 08:00 Kigali; `+1 day`, `+7 days`,
  `Back to baseline`. Moving the clock delivers due reminders (simulated, in-app only).
- **Simulate care-team confirmation (demo)** — DEMO, represents an action in the Clinical Portal:
  the nearest planned next step's linked referral / follow-up is recorded as completed with
  `clinician_confirmation` evidence by the simulated clinician `persona-clin-alpha1`
  (audit `demo.simulated_staff_action`), so the step shows as DONE (Scenario 1).
- **Fault toggles** (FND-07 `FaultConfig`, persisted in the local database):

| Toggle                 | FaultConfig                     | Effect                                                                        |
| ---------------------- | ------------------------------- | ----------------------------------------------------------------------------- |
| Slow network           | `latencyMs`                     | every repository call waits (loading states)                                  |
| Server errors (500)    | `serverErrorRate = 1`           | reads show an error with Retry; writes keep the same idempotency key on retry |
| Service unavailable    | `dependencyUnavailableRate = 1` | simulated verification is unavailable — no identity is ever fabricated (T-07) |
| Conflict on next write | `conflictOnce` (active patient) | the next write returns `CONFLICT` and shows the latest saved state            |
| Offline and scenarios  | FND-10 `DemoToolsSheet`         | offline banner; load a cross-app scenario                                     |

  DemoBanner first, a screen header, every pressable labelled and ≥ 44 × 44 pt
  (`expectMinTouchTarget` / `walkAllRoutes` from `@laif/test-utils/native`), exposed

  error500 / denied / conflict / success / offline (scenario or reasoned N/A) + a `fetch` spy
  proving no network call.

  is asserted N/A).
- `src/__tests__/safety/forbiddenContent.test.tsx` — every route × persona × EN/RW: no score /
  forecast / risk / diagnosis / insurance / credit / eligibility wording, no unapproved

  minute 12–13, representative scope, plus `consent`, `reminder-opt-out`, `correction-request`,
  `shell`. Maestro run order and `clearState` are in `.maestro/config.yaml`.

## Known limitations

- **Offline:** not applicable — the wallet is local-only ("Works without internet" on About this
  demo); the offline toggle only shows the banner.
- **Re-consent does not re-plan reminders** (open product-owner decision, CONSISTENCY_REVIEW §16):
  withdrawing consent cancels scheduled reminders; giving consent again keeps the stored
  preference but schedules nothing until the citizen confirms reminders again (toggle / timing).
- **CTZ-P2 has an approved appointment in the seed**, so the Next steps empty state is not visible
  with a seeded persona; it is covered by the UX-state matrix (records removed in a test store).
- **Web target:** tab stacks stay mounted (hidden from screen readers; inactive tabs take no
  pointer events). Focus-to-title and screen-reader announcements are native-only.
- Reminders are simulated in-app notifications only (no SMS, no push server); one on-device test
  notification can be previewed.
- Cross-app scenarios (wallet ⇄ Clinical Portal) are simulated by demo tools; real cross-app
  import / export is out of scope (REL track). No store builds.
- Maestro flows need an emulator / simulator with the app open (not part of `pnpm verify`).
